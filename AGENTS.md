# Repository Guidelines

## Project Overview

This repository is the documentation site for modding **Neodash** (Steam app `1514950`). It uses Astro and Starlight. Some example pages, the favicon, and the unused Houston image are still starter placeholders; do not treat them as established Neodash content or architecture.

## Architecture & Data Flow

- `astro.config.mjs` registers Starlight and defines site metadata and sidebar navigation.
- `src/content.config.ts` declares one `docs` collection using Starlight's `docsLoader()` and `docsSchema()`.
- Starlight discovers `.md` and `.mdx` files under `src/content/docs/`, validates their frontmatter, and maps file paths to routes. For example, `guides/example.md` becomes `/guides/example/`.
- Frontmatter supplies page metadata and layout data; Markdown/MDX supplies the body. MDX may import Starlight components, as `src/content/docs/index.mdx` does.
- Navigation is currently mixed: Guides uses explicit slugs in `astro.config.mjs`; Reference is autogenerated from its directory.
- There is no API/server layer, persistence, dependency-injection container, custom state management, or client-side async/error-handling pattern. Keep content-first changes simple unless a feature requires runtime code.

## Key Directories

- `src/content/docs/`: documentation pages and route hierarchy. Use lowercase directories and filenames.
- `src/assets/`: images processed by Astro and referenced relatively from content.
- `public/`: files served unchanged, such as `public/favicon.svg`.
- `dist/`: generated production output; never edit it directly.

## Development Commands

Run commands from the repository root:

```sh
bun install
bun run build
bun run preview
bun run astro -- --help
```

Start development in background mode so it remains manageable:

```sh
bun run astro -- dev --background
bun run astro -- dev status
bun run astro -- dev logs
bun run astro -- dev stop
```

`bun run dev` and `bun run start` both launch foreground `astro dev`; avoid them when an assistant starts a persistent server. No lint, format, typecheck, test, coverage, or deploy script is configured.

## Code Conventions & Common Patterns

- JavaScript/TypeScript is ESM. Existing config code uses tabs, single quotes, semicolons, and trailing commas in multiline structures. No formatter enforces these choices; preserve nearby style.
- TypeScript inherits Astro's strict preset from `tsconfig.json`. Do not weaken it or add path aliases casually.
- Documentation pages begin with YAML frontmatter containing at least `title` and `description`; use two-space YAML indentation.
- Use task-oriented prose for guides and concise factual prose for reference pages. Keep route categories and filenames lowercase.
- In MDX, place imports after frontmatter and use PascalCase component names such as `Card` and `CardGrid`.
- Add navigation deliberately: use an explicit `slug` for curated ordering or an `autogenerate.directory` entry for directory-driven sections.
- Prefer Starlight layouts, components, and content schemas over local abstractions. No repository-specific conventions yet exist for errors, async work, dependency injection, or state; introduce those only with an actual runtime requirement.

## Important Files

- `astro.config.mjs`: Astro/Starlight integration, site metadata, social links, and sidebar.
- `src/content.config.ts`: docs collection loader and schema.
- `src/content/docs/index.mdx`: landing route and example of Starlight components/frontmatter.
- `package.json`: package scripts and direct dependencies.
- `bun.lock`: authoritative dependency lockfile.
- `tsconfig.json`: Astro strict TypeScript configuration.
- `README.md`: starter workflow notes; its product copy is stale until rewritten for Neodash.

## Runtime/Tooling Preferences

- Use **Bun** for installation and package scripts; `bun.lock` is the only lockfile. Do not add npm, pnpm, or Yarn lockfiles.
- The package is ESM (`"type": "module"`). No exact Bun or Node version is pinned.
- Direct dependencies are Astro, Starlight, and Sharp. There is no frontend framework, server adapter, CSS toolchain, linter, formatter, or CI/deployment configuration.
- Neodash's internal Unreal project is `Runway` and the shipped game is based on **Unreal Engine 4.26.2**. Match UE tooling and cooked assets to UE 4.26.2.
- Cover both established modding paths: **UE4SS** for runtime scripting, hooks, and inspection, and classic **UE4 Pak overrides** for cooked-asset replacement. These are external modding workflows, not proof that the stock game bundles a loader.
- Pak overrides must preserve original Unreal package paths and serialization compatibility. Keep stock files recoverable, document tested game/tool versions, and separate confirmed behavior from experiments.
- Consult the official [Astro documentation](https://docs.astro.build/) and [Starlight documentation](https://starlight.astro.build/) before changing framework behavior. Use the relevant Astro guides for routing, components, framework integrations, content collections, styling, or internationalization rather than inventing a second convention.

## Testing & QA

No automated test framework, test files, fixtures, snapshots, CI checks, coverage configuration, or coverage target exists. Do not claim or invoke `bun test` as a repository workflow.

For content or configuration changes:

1. Run `bun run build` to validate content schemas, routes, and the production build.
2. Exercise the affected route through the background dev server or `bun run preview` and inspect the rendered page.
3. If runtime behavior is added later, add a test framework only as part of that explicit feature and document its commands here.
